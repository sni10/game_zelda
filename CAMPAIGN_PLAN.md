# 🎯 CAMPAIGN_PLAN — миссии, цели, кампания танков

План эпика, обсуждённый и утверждённый 2026-09-14. Дублирует тело GitHub issue (см. ссылку
в `BACKLOG.md`, когда появится) — здесь более подробная версия с обоснованиями.

Закрывает открытый вопрос из `DESIGN.md` → «Структура карт?»: ответ — **отдельные уровни**
(не одна большая карта с зонами, не процедурные данжи). Сеттинг при этом меняется — см. ниже.

---

## Решение по сеттингу (заменяет ADR от 2026-04-27 в DESIGN.md)

**Было:** морпех vs ксеносы, готический космос-хоррор (Warhammer 40k vibe).
**Стало:** игрок — маленький танк. Руины города / загород / леса — в духе Battle City,
не cartoon, серьёзная подача.

По ходу обсуждения рассматривался гибрид «часть миссий пешком (морпех), часть на танке» —
**отклонено**: потребовало бы хранить два независимых состояния прогрессии/лута/оружия
(набор морпеха и набор танка) и синхронизировать их при переключении режима на каждой
смене карты. Ради «сохранить механики, поменять текстуры» это неоправданная сложность.
**Решение:** один персистентный player state, один режим — танк. Пехотный режим не
реализуем, пока не появится причина сильнее эстетики.

Механика движения не меняется вообще — WASD относительно прицела уже называется в
`CLAUDE.md` «танковым движением», буквально то, что нужно для танка без переделок.
Оружейные слоты/боеприпасы/HP/экипировка — та же система, что и сейчас, просто визуальные
темы (`weapon_id` → название/цвет) со временем переименуются под танковую тематику.

## Архитектура

Три новых маленьких класса поверх существующих паттернов проекта (Strategy — уже
используется для `Weapon` и `AIBehavior`, ничего нового по духу не вводим).

### `MissionObjective` (Strategy, `src/entities/mission_objective.py` или `src/systems/`)

```
class MissionObjective(ABC):
    def is_complete(self, world) -> bool: ...
    def progress(self, world) -> str:  # для HUD, например "Босс: жив" / "Врагов: 12"
        ...
```

Стартовые реализации:
- **`DefeatBossObjective`** — флагманский тип. Готово, когда конкретный заспавненный босс
  мёртв. **Технически можно проскочить мимо всех рядовых врагов и убить только босса** —
  это осознанно разрешено дизайном (не запрещаем чем-то вроде «сначала зачисти карту»),
  но без прокачки/оружия так далеко не пройти на практике — баланс должен обеспечивать
  это сам, не искусственный гейт.
- **`ClearAllEnemiesObjective`** — готово, когда `world.enemy_manager.alive_count() == 0`.
  Нужен флаг `respawn_enabled` на `EnemyManager` (сейчас всегда авто-респавнит убитых —
  специально для открытого мира, но прямо противоречит «зачисти карту = цель»). На
  миссионных картах респавн должен быть выключаем через `Mission`.

Позже, без переделки остального (Open/Closed — новый класс, а не правка существующих):
`CollectLootObjective`, `SurviveTimeObjective`, `ReachAreaObjective`.

### `Mission` (данные, не поведение)

Поля: `map_file`, `objective: MissionObjective`, `title`, тема (`enemy_type_ids` — какие
типы из `EnemyFactory` спавнятся, палитра/tint для текстур игрока и мира), `boss_type_id`
(если есть DefeatBoss-цель — какого врага заспавнить как босса и где).

### `Campaign` (последовательность миссий)

Список `Mission`, текущий индекс. На старте миссии строит новый `World(map_file=...)`
(как сейчас, ничего нового), спавнит игрока в `player_start` карты, применяет тему.
Каждый кадр спрашивает у активной цели `is_complete()`. По готовности — `MapTransition`,
затем следующая `Mission` или, если миссий больше нет, экран победы кампании.

Мир как был «один за раз» — так и остаётся (ADR от 2026-04-26, multi-world не
возвращаем). Смена карты — это замена `self.world`, не второй активный мир.

### `MapTransition` — переход с затуханием

Маленький self-contained класс: `start()` → `update(dt)` → `draw(screen)`. Состояния
fade-out (чёрный прямоугольник alpha 0→255) → замена `self.world` в момент полной
черноты → fade-in (255→0). Не требует нового `GameState` обязательно — можно как оверлей
поверх `PLAYING`, решается в реализации.

### Экран статистики миссии

Новый `GameState.MISSION_COMPLETE` + `MissionCompleteScreen`, по образцу уже существующих
`GameOverScreen`/`SaveLoadMenu` (тот же паттерн: класс экрана + `handle_input()` +
`draw()`, пауза приходит бесплатно через существующий guard в `Game.update()`).
Показывает срез `GameStats` за миссию (убийства, время, полученный урон, найденный лут).
`GameStats` сейчас копит всё за ран целиком — нужен снапшот значений на старте миссии и
diff на завершении, а не новая система статистики.

## Новый враг: босс с тройным щитом

Механика щита **уже реализована и уже проверена в бою** — `EnemyStats.shield_max_hits`
(см. `src/entities/enemy.py`), причём `heavy` уже использует `heavy_shield_hits = 3` в
`config.ini`. Босс — это, по сути, `HeavyEnemy`-профиль с более высокими статами и
уникальным статусом, не новая система:
- Новый `type_id` (например `boss_heavy`) в `EnemyFactory`, секция `[enemies]` с
  префиксом `boss_` — крупный размер, много HP, медленный, `boss_shield_hits = 3`.
- Нужен способ пометить врага как «босс» для `DefeatBossObjective` — простейший вариант:
  флаг `is_boss` на `Enemy` или отдельный список `EnemyManager.boss_enemies`, не общий
  `alive_count()`.
- AI на первую итерацию — существующий `ChaseBehavior` с увеличенным радиусом агро.
  Фазы/уникальные атаки — сознательно отложены (см. «Вне scope» ниже).

## Dev-этап (сейчас) — 2 карты, полный цикл механики

Итоговый план — 10 миссий/10 карт, но для отладки самого механизма хватает **двух уже
существующих карт**:

1. **`main_world`** (малая) — миссия 1, цель `DefeatBossObjective`: заспавнить одного
   `boss_heavy`, плюс обычный ростер врагов вокруг (можно попытаться проскочить к боссу
   напрямую — редко получится без снаряжения).
2. Победа → `MapTransition` (fade) → **`big_world`** (крупная) — миссия 2, любая цель на
   выбор для обкатки (`ClearAllEnemiesObjective` подойдёт, раз респавн уже умеет
   выключаться).
3. `MissionCompleteScreen` после каждой миссии.

Как только цикл `цель → переход → следующая карта → статистика` работает на двух картах —
это тот же код, что понадобится для остальных восьми. Контента (карт/боссов) станет
больше, механизм — нет.

## Вне scope этого эпика (сознательно)

- Остальные 8 из 10 карт — контент, не архитектура, добавляются позже тем же `tools/gen_big_world.py`-подходом.
- Фазы боссов, несколько уникальных боссов с разными механиками — `BACKLOG.md` → «Боссы с фазами» (v0.7+), эта итерация даёт только первого простого босса.
- Сундуки/лут-контейнеры на карте — уже отдельный пункт `BACKLOG.md` v0.4.2, не пересекается напрямую, но естественно сочетается (лут по пути к боссу).
- Пеший режим игрока — отклонён выше, не реализуем.
- Ветвящаяся/нелинейная кампания, выбор миссии из меню — только линейная последовательность 1→2→...→10 для v1.
