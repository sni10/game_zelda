# CLAUDE.md

Этот файл предоставляет руководство для Claude Code (claude.ai/code) при работе с кодом в данном репозитории.

Player-facing описание игры (features, управление, установка) — в [README.md](README.md) /
[README_RU.md](README_RU.md). Этот файл — для разработки/агентов: архитектура, ветвление, CI/CD.

## Основные команды разработки

### Запуск игры
```bash
python main.py
```
Основная точка входа находится в корневой директории для удобства.

### Тестирование
```bash
# Запустить все тесты с покрытием
pytest tests/ -v --tb=short --cov=src --cov-report=xml --cov-report=term-missing

# Запустить конкретный тестовый файл
pytest tests/unit/test_player.py -v

# Запустить конкретный тестовый метод
pytest tests/unit/test_player.py::TestPlayer::test_movement -v
```

### Качество кода
```bash
# Форматирование кода
black src/ tests/

# Линтинг кода
flake8 src/ tests/

# Проверка типов
mypy src/
```

### Зависимости
```bash
# Установить все зависимости
pip install -r requirements.txt

# Установить для разработки (включает инструменты тестирования и линтинга)
pip install pygame pytest pytest-cov pytest-mock black flake8 mypy coverage
```

## Обзор архитектуры

Это 2D игра в стиле Zelda, построенная на Python и Pygame с соблюдением принципов ООП, SOLID и DRY.
Простая single-world архитектура — без ECS, мульти-миров, Z-переходов и порталов: эти идеи
рассматривались на раннем этапе (см. `docs/tech_draft/`), но были признаны оверинжинирингом для
текущего этапа разработки и не реализованы.

### Основной архитектурный паттерн
Игра использует модульную entity-component систему с четким разделением обязанностей:
- Класс `Game` (`src/core/game.py`) управляет основным игровым циклом и координирует все системы
- Конфигурация загружается из `config.ini` через систему `ConfigLoader`
- Все игровые настройки централизованы и валидированы по типу
- Оружие использует Strategy pattern (`Weapon` и подклассы), боевые системы (`PlayerCombat`,
  `EnemyManager`, `ProjectileManager`) не занимаются коллизиями напрямую — они возвращают
  зоны поражения/события, а вызывающий код (`Game`) решает, что с ними делать

### Ключевые паттерны проектирования
- **Композиция над наследованием**: Сущности составляются из поведений, а не глубокого наследования
- **Конфигурационно-ориентированный**: Все игровые параметры вынесены в `config.ini`
- **Delta Time**: Правильное движение, независимое от частоты кадров, с использованием delta time
- **Система камеры**: Мир 2000x2000 с плавным следованием камеры и ограничениями границ
- **Strategy (оружие)**: `Weapon` — абстрактный базовый класс, подклассы (`MeleeWeapon`,
  `PolearmWeapon`, `RangedWeapon`, `BurstRifle`, `ShotgunWeapon`, `AoeWeapon`) переопределяют
  только нужные параметры/`get_attack_rects()`. `WEAPON_CATALOG` — единственный источник правды
  для создания оружия по `weapon_id` (сохранения, инвентарь, каталог)

## Текущие игровые возможности

### Система движения игрока
- **Движение относительно прицела ("танковое")**: W/S — вперёд/назад вдоль направления взгляда
  (`aim_dx`, `aim_dy`), A/D — вбок (strafe), перпендикулярно взгляду. Игрок вращается на месте
  мышью, а WASD двигает его относительно того, куда он сейчас смотрит — не по мировым осям.
  Стрелки движение не дают.
- **Нормализация скорости**: Правильная нормализация диагонального движения (120 пикселей/секунду
  базово, `config.ini` → `[player] player_speed`)
- **Спринт**: Shift увеличивает скорость (`player_sprint_multiplier`, по умолчанию 1.8x)
- **Размер игрока**: 32x32 пикселя с индикатором направления взгляда (белая точка)
- **Плавное движение**: Независимое от частоты кадров движение с delta time

### Боевая система
- **Гибкие слоты оружия**: старт с 2 слотов (мечи), разлочка до 8 по уровню
  (`config.ini` → `[progression] weapon_slot_unlock_levels`). Любой слот может держать любое
  оружие из `WEAPON_CATALOG` — свободное назначение, без привязки к melee/ranged
- **Ближний бой**: `MeleeWeapon` (меч, вплотную), `PolearmWeapon` (копьё, с зазором) —
  мгновенные прямоугольные зоны поражения по направлению прицела (360°, не только 8 направлений)
- **Дальний бой (реальная баллистика)**: `RangedWeapon` (Rifle), `BurstRifle` (SMG, очередь из
  3 пуль на 1 патрон), `ShotgunWeapon` (5 пуль веером на 1 патрон) — спавнят `Projectile`,
  который сам летит и проверяет столкновения по кадрам в `ProjectileManager` (гасится о стену/
  границу мира/врага)
- **AoE**: `AoeWeapon` (бомба) — большая зона поражения с задержкой
- **Патроны**: общий пул `"bullets"` на всё ranged-оружие, магазин/резерв, R или ПКМ — перезарядка
- **Смена оружия в слоте**: через экран инвентаря (`I`, см. ниже) — перетаскивание иконки из
  каталога всего оружия на нужный слот (`PlayerCombat.set_slot_weapon`)
- **Визуальные эффекты**: Игрок краснеет во время атаки, цветная зона показывает область атаки
  (цвет зависит от оружия)

### Враги
- **Типы**: Light/Heavy/Fast (`EnemyStats`, `enemy_factory.py`) — разный HP/скорость/урон
- **Патрулирование и погоня**: `EnemyManager` + поведения в `enemy_ai.py`
- **Контактный урон и knockback**: с i-frames у игрока, cooldown атаки у врага
- **Дроп лута**: XP-орбы, монеты/сердечки (в зависимости от HP игрока), патроны — через
  `PickupManager`

### Игровой мир
- **Большой открытый мир**: 2000x2000 пикселей для исследования, загружается из ASCII-карты
  (`data/main_world.txt`)
- **Система коллизий**: Столкновения с препятствиями и границами мира
- **Terrain**: несколько типов ландшафта с уроном/замедлением (`src/world/terrain.py`)

### Камера, HUD и инвентарь
- **Умная камера**: Автоматическое центрирование на игроке с ограничениями границ
- **Мини-карта**: позиция игрока, препятствия, область видимости камеры
- **HUD**: здоровье, слоты оружия, патроны текущего оружия
- **Инвентарь (`I`)**: всегда показывает все 8 слотов оружия — ещё не разлоченные видны, но
  неактивны (вдвое меньшая непрозрачность), плюс ряд-каталог всего доступного оружия для
  drag-and-drop в слот (`src/ui/inventory_screen.py`)
- **Система отладки**: F1 для включения информации о координатах, FPS, состоянии игрока

### Управление
- **Мышь**: прицел (360°), игрок всегда смотрит на курсор
- **WASD**: движение относительно прицела (вперёд/назад/вбок, см. выше)
- **Пробел / ЛКМ**: атака/выстрел в направлении прицела
- **Shift**: спринт
- **1-8**: выбор слота оружия
- **R / ПКМ**: перезарядка
- **I**: открыть инвентарь
- **F1**: отладочная информация
- **F5 / F9**: quicksave / quickload
- **ESC**: меню

## Детали проекта

### Система конфигурации
Игра использует продвинутую систему конфигурации в `src/core/config_loader.py`:
- Валидирует все значения конфигурации при запуске
- Предоставляет типобезопасные аксессоры: `get_config()` и `get_color()`
- Централизована в `config.ini` с секциями для дисплея, мира, игрока, атаки, патронов,
  прогрессии, врагов, цветов, отладки и генерации мира

### Взаимосвязи сущностей
- `Player` (`src/entities/player.py`): движение, здоровье (делегирует `PlayerStats`), боевая
  система (делегирует `PlayerCombat`) — 360°-прицел мышью, независимый от движения
- `PlayerCombat` (`src/entities/player_combat.py`): слоты оружия, атака, патроны/перезарядка
- `Weapon` (`src/entities/weapons.py`): Strategy pattern, см. выше
- `Enemy` / `EnemyManager`: патрулирование, атака, дроп лута
- `Projectile` / `ProjectileManager`: баллистика ranged-оружия
- `World` (`src/world/world.py`): камера, коллизии, генерация мира
- Все сущности следуют единообразным паттернам для позиции, размера и обнаружения коллизий

### Стратегия тестирования
Тесты организованы по типам:
- Юнит-тесты в `tests/unit/` тестируют отдельные компоненты изолированно (по файлу на систему:
  `test_player.py`, `test_weapons.py`, `test_projectile.py`, `test_combat_loop.py`,
  `test_inventory_screen.py`, `test_save_system_roundtrip.py` и т.д.)
- Тесты конфигурации в `tests/config/` тестируют загрузку и валидацию конфигурации
- pygame инициализируется с `SDL_VIDEODRIVER=dummy` — тесты не открывают окно

## Стратегия ветвления и CI/CD

Этот проект следует **GitFlow**:
- **`main`** — готовый к продакшену код
- **`stage`** — предпродакшн тестирование
- **`dev`** — интеграционная ветка для фич
- **`feature/*`** — новая функциональность на основе `dev`
- **`release/*`** — подготовка релиза на основе `stage`
- **`hotfix/*`** — срочные исправления на основе `main`

### Поток веток
```
feature/*   -> dev
dev         -> stage
stage       -> release/*
release/*   -> main + dev
hotfix/*    -> main + dev
```

Процесс: фичи разрабатываются в `feature/*` → мержатся в `dev` для интеграции → `dev` мержится в
`stage` для тестирования → снапшот-релиз из `stage` в `release/*` → релиз мержится в `main`, `dev`
и `stage`.

### Автоматизированные процессы (GitHub Actions)

**1. `python-tests.yml`** — тестирование кода
- Триггер: push/PR в `main`, `dev`, `stage`
- Шаги: checkout → Python 3.10 → `pip install -r requirements.txt` → `pytest` с покрытием →
  отчёт в Codecov
- Цель: не дать смержить код, который ломает тесты

**2. `auto-sync-branches.yml`** — автосинхронизация веток
- Триггер: push в `dev` или `stage`
- При push в `dev`: если есть новые коммиты относительно `stage` → создаёт ветку
  `auto-sync/dev-to-stage-<timestamp>` → открывает PR `dev → stage`
- При push в `stage`: аналогично, PR `stage → main`
- PR создаётся автоматически, с списком коммитов в описании — без ручного вмешательства

**3. `versioning.yml`** — автоматические релизы
- Триггер: push в `main` (или `workflow_dispatch` вручную)
- Определяет тип версии по коммитам: `BREAKING CHANGE` → major, `feat:` → minor, всё
  остальное → patch (semantic versioning)
- Создаёт git-тег `vX.Y.Z`, GitHub Release с changelog (список коммитов, статистика,
  ссылки на diff), пушит тег в репозиторий

### Полный цикл
1. Разработка фичи → push в `dev` → `python-tests.yml` проверяет код, `auto-sync-branches.yml`
   открывает PR `dev → stage`
2. Тестирование → мерж PR в `stage` → `python-tests.yml` проверяет код, `auto-sync-branches.yml`
   открывает PR `stage → main`
3. Релиз → мерж PR в `main` → `python-tests.yml` проверяет код, `versioning.yml` создаёт релиз

## Важные детали реализации

### Технические характеристики (`config.ini`)
- Размер окна: 1024x768 пикселей (`[display]`)
- Размер мира: 2000x2000 пикселей, тайл 32x32 (`[world]`)
- 60 FPS с delta time для независимости от частоты кадров
- Скорость игрока: 120 пикселей/секунду, нормализована для диагонального движения
  (`[player] player_speed`)

### Система отладки
- Нажмите F1 для переключения отображения отладочной информации
- Утилиты отладки в `src/utils/debug.py` предоставляют информацию во время выполнения
- Конфигурация отладки контролируется через config.ini
